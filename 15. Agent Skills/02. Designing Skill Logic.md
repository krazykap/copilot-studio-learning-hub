# 02. Designing Skill Logic: Contracts, Scope, and Failure Paths

## Overview
A Skill can be created correctly — right name, discoverable description, clean instructions — and still be badly designed underneath. This is the layer where that happens: the actual logic the Skill runs once the orchestrator hands it a matching request. Get this part wrong and you end up with something that works in every demo and breaks the first time a real user, a slow API, or an unexpected edge case shows up. This deep dive treats Skill logic design as what it actually is: application design, not conversation design.

## What are Agent Skills?
Agent Skills are the building blocks of an Agent's capabilities. Agent Skills are a lightweight, open format for extending AI agent capabilities with specialized knowledge and workflows. They define how an Agent can respond to specific requests, perform tasks, and interact with users or other systems. Each Skill encapsulates a specific piece of functionality, allowing for modular and reusable components within the Agent's architecture.

At its core, a skill is a folder containing a SKILL.md file. This file includes metadata (name and description, at minimum) and instructions that tell an agent how to perform a specific task. Skills can also bundle scripts, reference materials, templates, and other resources.

### Why Agent Skills Matter?
Agent Skills matter because they allow developers to extend the capabilities of AI agents in a modular and reusable way. By encapsulating specific functionality within a Skill, developers can create a library of Skills that can be easily shared, updated, and maintained. This modularity also enables better collaboration among teams, as different developers can work on different Skills without interfering with each other's work.

Agents are increasingly capable, but often don’t have the context they need to do real work reliably. Skills solve this by packaging procedural knowledge and company-, team-, and user-specific context into portable, version-controlled folders that agents load on demand. This gives agents:
- **Domain expertise:** Capture specialized knowledge — from legal review processes to data analysis pipelines to presentation formatting — as reusable instructions and resources.
- **Repeatable workflows:** Turn multi-step tasks into consistent, auditable procedures.
- **Cross-product reuse:** Build a skill once and use it across any skills-compatible agent.

### How Skills Work
When an agent receives a request, it evaluates the request against its available Skills to determine which Skill is best suited to handle the request. The agent then invokes the selected Skill, passing along any necessary context or parameters. The Skill executes its logic, performs the required actions, and returns a response to the agent, which can then present the results to the user or take further action as needed.

Agent loads Skills dynamically through progressive disclosure, in 3 stages:
1. **Discovery:** The agent identifies which Skills are available and relevant to the user's request. This may involve searching through a registry of Skills or evaluating metadata associated with each Skill.
2. **Selection:** The agent selects the most appropriate Skill based on the request and any additional context. This may involve evaluating the Skill's capabilities, performance history, or other factors.
3. **Execution:** The agent invokes the selected Skill, passing along any necessary parameters or context. The Skill executes its logic, performs the required actions, and returns a response to the agent.

#### 4 Stage Progressive Disclosure
Agent skills use 4 stage progressive disclosure to handle requests:
- **Advertise (~100 tokens per skill):** The agent advertises its capabilities to the user, providing information about the available Skills and their functionality.
- **Load (< 5000 tokens):** The agent loads the selected Skill, initializing any necessary resources or dependencies.
- **Read Resources (as needed):** The agent reads any reference materials or documentation associated with the Skill, ensuring it has the necessary context to execute the Skill effectively.
- **Run Scripts (as needed):** The agent executes any scripts or executable code associated with the Skill, performing the required actions and returning a response to the user.

### Where Skills Fit in the Agent Architecture?
Agent Skills are a critical component of the overall agent architecture. They serve as the interface between the agent's core capabilities and the specific tasks or requests it needs to handle. By encapsulating functionality within Skills, agents can maintain a clean separation of concerns, allowing for easier maintenance, updates, and scalability.

Skills can be thought of as plugins or extensions that enhance the agent's capabilities without requiring changes to the core agent logic. This modular approach allows for greater flexibility and adaptability, enabling agents to evolve and improve over time as new Skills are developed and integrated.

## Specification
Agent Skills are defined by a specification that outlines the required structure, metadata, and instructions for creating a Skill. The specification ensures that Skills are consistent, discoverable, and compatible with the agent's architecture.

### Directory Structure
The directory structure of an Agent Skill is designed to be simple and intuitive, allowing developers to easily organize and manage their Skills. The following is a recommended directory structure for an Agent Skill:

<pre>
my-skill/
├── SKILL.md          # Required: metadata + instructions
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
├── assets/           # Optional: templates, resources
└── ...               # Any additional files or directories
</pre>

### `Skill.MD` format
The `SKILL.md` file is the core of an Agent Skill, containing metadata and instructions that define the Skill's functionality. The file should be structured in a clear and organized manner, with the following sections:

| Field | Required | Description |
|-------|----------|-------------|
| Name | Yes | The name of the Skill, which should be unique and descriptive. |
| Description | Yes | A brief description of the Skill's purpose and functionality. |
| Instructions | Yes | Detailed instructions on how the Skill should be executed, including any required parameters, expected inputs and outputs, and any relevant context or constraints. |
| Scripts | No | A list of any scripts or executable code associated with the Skill, along with instructions on how to run them. |
| license | No | Information about the licensing and usage terms for the Skill, if applicable. |
| allowed-tools | No | A list of any external tools or libraries that the Skill may require, along with instructions on how to install and configure them. |
| metadata | No | Any additional metadata that may be relevant to the Skill, such as version information, author details, or tags for categorization. |
| references | No | A list of any reference materials or documentation that may be useful for understanding or using the Skill. |

#### Minimal Example
<pre>
Skill.md
---
name: "Data Analysis Skill"
description: "A Skill that performs data analysis on provided datasets."
instructions: |
  1. Accept a dataset in CSV format as input.
  2. Perform statistical analysis on the dataset, including mean, median, and standard deviation calculations.
  3. Generate visualizations of the data, such as histograms and scatter plots.
  4. Return a summary report with the analysis results and visualizations.
---
</pre>

#### Full Example
<pre>
Skill.md
---
name: "Data Analysis Skill"
description: "A Skill that performs data analysis on provided datasets."
instructions: |
  1. Accept a dataset in CSV format as input.
  2. Perform statistical analysis on the dataset, including mean, median, and standard deviation calculations.
  3. Generate visualizations of the data, such as histograms and scatter plots.
  4. Return a summary report with the analysis results and visualizations.
metadata:
  version: "1.0.0"
  author: "Jane Doe"
license: "MIT"
allowed-tools:
  - pandas
  - matplotlib
compatibility:
  - Python 3.8+
validation:
  - Ensure the input dataset is in CSV format.
  - Validate that the dataset contains numeric columns for analysis.
file-references:
  - scripts/analyze_data.py
  - references/data_analysis_guide.pdf
---
</pre>

## Providing Skills to an Agent
When providing Skills to an agent, it is important to ensure that the Skills are well-documented, tested, and compatible with the agent's architecture. Developers should follow best practices for Skill development, including version control, code reviews, and thorough testing to ensure that the Skills function as intended.

It involves 3 building blocks:
- Providor: The entity responsible for creating and maintaining the Skill, ensuring that it meets the required specifications and is compatible with the agent's architecture.
- Sources: The source code, scripts, and resources that make up the Skill, including the `Skill.md` file and any associated files or directories.
- Builder: The agent or system that loads and executes the Skill, ensuring that it is invoked correctly and that the results are returned to the user or other systems as needed.

### Types of Skills:
- **File-based Skills:** These Skills are defined by a set of files and directories, including the `Skill.md` file, scripts, references, and assets. They can be easily shared and version-controlled, allowing for collaboration among developers.
- **Code-based Skills:** These Skills are defined by a set of code modules or libraries that encapsulate specific functionality. They can be integrated into the agent's architecture and invoked programmatically, allowing for greater flexibility and customization.
- **Class-based Skills:** These Skills are defined by a set of classes or objects that encapsulate specific functionality. They can be instantiated and invoked as needed, allowing for greater modularity and reusability.
- **MCP-based Skills:** These Skills are defined by a set of microservices or APIs that encapsulate specific functionality. They can be invoked over the network, allowing for greater scalability and integration with other systems.

## Security Best Practices
When designing and implementing Agent Skills, it is important to follow security best practices to ensure that the Skills do not introduce vulnerabilities or risks to the agent or the systems it interacts with. Some key security considerations include:
- Reviewing and validating any external dependencies or libraries used by the Skill to ensure they are secure and up-to-date.
- Implementing proper input validation and sanitization to prevent injection attacks or other malicious inputs.
- Ensuring that any sensitive data or credentials used by the Skill are stored securely and not exposed in logs or error messages.
- Implementing proper access controls and permissions to restrict access to the Skill's functionality and resources as needed.

## Key Takeaways
- Agent Skills are modular components that extend the capabilities of AI agents, allowing for specialized knowledge and workflows.
- Skills are defined by a specification that outlines the required structure, metadata, and instructions for creating a Skill, ensuring consistency and compatibility with the agent's architecture.
- Skills can be provided to an agent in various formats, including file-based, code-based, class-based, and MCP-based Skills, each with its own advantages and use cases.
- Security best practices should be followed when designing and implementing Agent Skills to ensure that they do not introduce vulnerabilities or risks to the agent or the systems it interacts with.
- By following best practices for Skill development, including version control, code reviews, and thorough testing, developers can create reliable and effective Skills that enhance the capabilities of AI agents and provide value to users.
